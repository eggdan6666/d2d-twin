**路由信号本身失效，两处独立原因**:
1. 覆盖率被 `parse_parts` 正则卡死——只有 `larger: A or B?` 句式进校验，23/37(62%)；X000–X009、C017、C019、C057、C058 共 14 题（`Compare the datasheet-specified values…` / `For the datasheet parameter…` 句式）对校验器不可见（hybrid_cross.json 中 verify=null），永远停在 3B。

**oracle 上界（用本次 3B 与 API 的逐题并集，替代纸面成本模型）**: 完美路由在现有正则覆盖下仍只有 **7/37 = 18.9%**（升级域并集 5/23 + 未覆盖 14 题里 3B 的 2 题），**低于纯 API 的 8/37 = 21.6%**；若把校验域扩展到全部 37 题，并集上界 10/37 = 27.0%。结论修正: 该架构瓶颈不是"要不要升级"，而是"路由器检不出错 + 覆盖不到 14 题"；在修好这两点前，混合路由不建议接入 app 30 题评测。
