## 判断

**有条件可行，建议收紧范围后冲刺。** 三层系统可以支撑一篇长文，但“拼接已有模块 + 增加页数”不足以证明方法创新。建议以“来源约束、显式未知、条件执行、独立验收与补丁拒绝共同构成可审计工程智能体闭环”为主贡献，RAG 和修复分别验证这个契约在上、下游的作用。人类／独立审核者的晋升权、冲突处置和工作量应有明确记录，以呼应 Hybrid Human Agentic-AI 的主题。

不能把冻结 MD5、参考实现全绿或确定性重放写成“V&V 最高标准”；它们分别证明字节稳定、契约一致或本地可重现性，不证明规范本身正确、硅片等价、物理时序或部署安全。现阶段更准确的范围是“数据手册约束下的寄存器行为仿真及有界验证”。若沿用数字孪生名称，需在文中明确这种抽象范围。

## 上游接口与误差门禁

推荐数据流：PDF／解析文本 → 检索证据 → Silver 候选 → schema／来源／条件审核 → 单写入者晋升 manifest → 只读 Gold → 合成 → 独立评分。自动抽取不写正式 `d2d/ir/`，测试 oracle 不从同一份未经审核 Silver 生成，避免错误规范与实现相互印证。

|契约层|必要字段或规则|接受／拒绝原则|
|---|---|---|
|身份与溯源|器件／变体、PDF SHA-256、修订号、物理页及印刷页、表／图号、chunk／span、抽取运行 ID|错器件、错版本、无原页证据不晋升|
|字段几何|inventory_field_id、地址、位宽、位段、有效 mask、读写别名|离散语义零容错；地址唯一、位段合法、不得重叠／越界|
|行为|访问权限、reset value 与 known_mask、read_action、write_action、触发条件、前后状态及资格化完成事件|未知 reset 不填 0；冲突不由模型投票消除；动作必须有独立来源|
|输入域|legal_values、跨字段前置条件、variant／mode／history profile、excluded clauses|未定义编码不猜忽略／钳位；不满足条件明确 OutsideContract／排除，不能记通过|
|准入|schema version、policy version、审核结论与证据 ID、晋升者、IR／harness／prompt hashes|来源结论与执行验收分开；候选 schema 不强行转换成旧 v1 语义|

“零容错”适用于被准入的离散规范，不要求抽取器每次都成功；允许它弃答并报告覆盖率。表示差异可确定性归一化，例如十六进制／十进制、单位换算；它们不能改变物理含义。连续量容差仅能来自来源给定精度及事先声明的比较规则，不能给地址、掩码或动作统一设置百分比容差。置信度只能分配审阅优先级，不能替代来源核验。

代码现实：`rag/hierarchical.py` 已有文档粗检、BM25／向量融合与邻接扩展；`rag/orchestrate.py` 输出问答文本和来源 chunk ID，未提供注册字段抽取器及正式 IR 适配器。邻接扩展不是已经验证的跨页表格重建；`rag/corpus.py` 的 chunk 元数据尚无完整 PDF 页／表格映射。需补抽取适配和证据定位。缓存目前主要按 chunk 数／字数等校验，应以内容版本隔离，避免并行修改语料后复用过期缓存。

## 两组实验的最小可审阅设计

### RAG

- 三臂使用同一 PDF 解析结果、切片、抽取模型、输出 schema、上下文预算与解码设置，先隔离检索策略效应。若要证明解析改进，另开解析消融；不能同时改解析器又把改善归因于分层检索。
- 冻结来源页／chunk 相关性标注，明确多证据与跨页表格匹配单位。报告检索 precision／recall、字段级地址／位段／访问／reset／动作 exact match、条件及冲突识别、弃答率、准入覆盖率、错误准入率和端到端适用断言成功率。
- 方案只写 L1 与 L3，没有定义 L2；应补抽取层指标定义或直接取消层级编号。结构 F1 与 bitfield accuracy 都要定义微／宏平均、分母、匹配键及遗漏／重复规则。
- 调参芯片与测试芯片分离；既有 20 芯片已反复使用，应如实声明探索性，或预留未调参芯片做确认。Gold、参考代码和隐藏 oracle 不进入检索库。RAG 三臂都记录向量分支是否实际启用，不能把降级 BM25 写成 Hybrid RAG。
- 先对跨页／动态／冲突类型各取代表性材料做接口 pilot，验收后按冻结设计扩大；pilot 结果单列。

### 修复

可以建设 `run_self_repair_benchmark.py`，但应作为新 runner，而非给当前 pilot 改文件名。现有代码只替换 MPU6050 的 write_register、固定 0x6B／DEVICE_RESET，使用本地 CUDA 模型及字符串／十六进制 literal 范围审计，尚无跨芯片多轮统计协议。

1. 冻结同一批初始失败代码，明确队列、模型、芯片、seed、sample ID。所有方法使用配对初始代码，推理 token／调用次数／反馈内容预算可比；“无反馈”也应有相同预算的再生成对照。
2. 若主张 reflection 有因果贡献，增加“相同结构化 patch + 相同反馈 + 无 reflection”臂。整文件重写对比结构化反思同时改变多个因素，只能支持整体策略效果。
3. 每轮落盘原码／patch／候选哈希、完整 prompt／response、trace／JUnit、预算、scope reject、回归、超时与接受状态。反馈测试与最终隐藏测试分离，防止反复利用同一黑盒得分调参。
4. AST 约束只允许目标类／方法及明确语义范围；禁止改 schema、IR、harness、断言或新增越界接口。当前 hexadecimal literal 白名单可被十进制写法／泛化循环绕过，不能当通用语义门禁。必须在所有已通过适用断言与独立非目标回归上验证，不只比较 passed 个数。
5. gate reject／超时／格式错误计入固定失败样本分母；拒绝后保留上个接受状态。分别报告原始候选回归与接受状态，不能用“门禁没有接受回归”掩盖候选回归风险。
6. 曲线称“截至第 R 轮的累计修复成功率”，并明确初始生成是否算一轮。经典 pass@k 适用于另一类候选采样估计，不能直接套到依赖上一轮反馈的修复链。报告全绿率、保留覆盖率、错误准入率、成本以及最终隐藏测试成功率；单个维度改善不等于完全修复。
7. 推断以芯片为独立组，对策略／模型作配对比较，重复生成与修复轮次保留组内关系。20 芯片便利样本的推断范围有限；历史 rho=-0.828 需按最终队列、复杂度定义、评分协议重新计算，并保留描述性边界。

## 并行分工边界

外部 AI 可并行做上游适配／评测与文稿草稿，但应由文件所有权和版本 manifest 约束，而不只口头约定“不改 Harness”。

- Codex／指定单写入者：候选规范、来源 policy、有界语义实现、新评分协议及最终 Gold 晋升；现有 v1 文件和历史分数继续只读。
- 上游协作方：专用 `eval/rag_extraction_<version>/`、候选抽取输出和拟议适配器；不编辑 `d2d/ir/`、冻结测试、已有签审或当前语义任务目录。
- 写作协作方：新 `paper/aei/` 或独立工作树；方法、相关工作与章节骨架先行，正式结果仅从锁定 manifest 派生。旧 `paper/main.tex` 和旧图保留。
- 各方使用独立输出目录、sandbox 与缓存，固定交接 schema、输入／输出哈希、完整日志与待审清单；同一文件只由一个写入者合并。并行评测不得因 tag 相同复用／清理对方 sandbox。
- 双栏 LaTeX 可作内部布局探索；投稿格式需以 AEI 当前作者指南为准。若已有短文实际发表或在审，需核实其状态并按出版方政策披露与区分新增贡献，不能仅依据本地 4 页 PDF 推断已发表。
