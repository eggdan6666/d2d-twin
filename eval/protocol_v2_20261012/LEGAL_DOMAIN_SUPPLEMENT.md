## LIS2DW12 CTRL2 两项隔离的独立复核

p.37 Table 32 的 bit5 为 `0` 并附脚注：必须为 0 才能正确工作。IR 字段名 `MUST_BE_ZERO` 的非零写入行为不应测试为普通 RO 硬连零；建议 `fixed_write=0`、`known_reset=true`，排除非法写 1 后的保持、钳位或持久性裁决。

同页 BOOT 文本明确：从 NVM 重载 trimming 参数，**操作结束后自动返回 0**，默认 0。它不是普通无限 RW 存储，也不等于任何写后瞬时读都会为 0。主协议尚无完成/时序模型时隔离写 1 的读回时序行为，合法基线保持 BOOT=0、已知初始值保留。SOFT_RESET 同页也明确 reset 后归零，但这一位已有复位动作编码，本任务不改主实现。

因此主任务对 MUST_BE_ZERO、BOOT 的隔离方案有来源支持。隔离的是非零刺激的行为保证，**不是删除有原文支持的默认 0 事实**。

## 保留全编码的反例与原说明更正

- **INA219 BADC/SADC**：p.20 Table 5 的 `0 X 00` 等设置包含 don't-care，0–7 均有分辨率定义；8–15 定义 12 位与平均采样。**0–15 都有定义**，不能看到表格行数较少就把 4–8 称为 Reserved。MODE 0–7、PG 0–3 同样全部定义（pp.19–20 Tables 4、6）。该页未声明这些编码的读回规范化，不能把功能等效的别名自动判成相同存储值。
- **ADS1115**：pp.25–26 Table 8-3 的 MUX、PGA、DR 都定义 0–7；PGA=5/6/7 均对应 ±0.256V，不属保留编码；COMP_QUE 0–3 均定义。OS 写触发、读状态，应保留动作/状态范围，不能以“合法 1”推导恒等持久性。
- **INA226**：pp.23–24 Tables 7-3–7-6，AVG/VBUSCT/VSHCT/MODE 的 0–7 全部定义；两个 power-down 编码不等于 Reserved。
- **TPS23861 INTERRUPT_TIMER.TMR**：p.68 §7.5.22 以完整 4 位 N 定义周期，并明确读回固件最后写入值；**0–15 都可用于直接存储契约**。
- **TMP102 CR**：p.15 Table 6-5 的 00/01/10/11 对应 0.25/1/4/8 Hz，默认 10=4 Hz。旧 IR 的 CR1 描述把 01 与 10 写错，不构成非法域，但需要未来输入修订时更正。
- **TMP1075 非 N orderable**：p.22 Table 7-8 中 R/F 两个 2 位域四个编码都定义。F=10/11 的故障次数对非 N 分别为 3/4，N 型为 4/6；不能混用型号。当前 IR 默认 00FFh 与非 N 支持一致。
- **TMP117 AVG**：p.27 Table 7-6 明确 no averaging/8/32/64，当前 IR 的 1/2/4/8 描述错误；四个编码仍全部合法。
- **TMP126 CONV_PERIOD**：SNIS209C p.29 Table 8-8 明确 0–7 全部定义，111=2 s / 0.5 Hz。旧 IR 的 111=4 s 描述错误，不影响合法域，但应在未来输入修订时更正。本轮核对了 p.29 原文，未进行测温或时序实测。
- **Bosch**：此前报告已核对 BME280 p.30 Table 28 的 filter `100, others→16`，所以 5–7 不应仅因没有逐行列出而剔除。BME280 mode 的实际 01/10 都是 forced，11 是 normal，旧 IR 的 mode 描述把 10 写成 normal；BME t_sb=6/7 实为 10/20 ms（p.30 Table 27），旧 IR沿用了 BMP280 的 2000/4000 ms。前者涉及执行后动态变化，后者不改变合法位域，但二者都削弱未修正提示词的解释。

## 强制默认写入规则与非法写后行为

TMP461 p.20 §8.6.1.4 明说 CONFIG 保留位必须一直设为 0；p.17 位图对应 [4:3] 和 [1:0]。这些位的复位 0 有证据，但不宜翻转再断言写保护。

TPS23861 p.68 §7.5.22 的 R27[7:4] 逐位 RESET/POR 明确为 0，并警告改变复位值会导致未期望行为。映射现 IR 的 `INTERRUPT_TIMER.ROM[7:4]`：保留已知复位 0，写入固定 0，隔离非零写后 oracle；字段名 ROM 不是源文对其功能的认证。

TPS23861 p.63 §7.5.16 的 R17[3:1] 不同：详细位表 RESET/POR 为 `Reserved`，正文警告不能改变复位值；p.45 Table 10 总览却给完整 GENERAL_MASK 初值 `1000,0000`。详细位表没有给三个字段的数值初值或 RO/ROM 行为，源内粒度存在歧义。主协议保守排除这三位数值复位和访问类型 oracle，写其它位时保持新建器件首次读回的这三位值（`preserve_write=true`），不能固定写零再宣称三个字段已独立确认。现 IR 精确映射为 `GENERAL_MASK.RSV3[3]`、`RSV2[2]`、`ROM1[1]`；`ROM1` 看似把源文 `R17[1]` 误解成 ROM，原文明确称 Reserved，不能断言它读取版本。此项源内歧义保留为未解决，不扩大到其它 Reserved 字段。

AD5592R p.29 与 p.36 关于 DAC_RD_EN 的联合核对还说明一个重要边界：字段表只写“0/1”可能是对一个多位使能条件的简述。早期速报中 `legal=[0,1]` 的表格独立解读已撤回；最终建议 [0,3]，以保留正文明确的 11 使能，同时对 01/10 暂不判定。不存在 AD5592R“3 是 Reserved”的原文证据。
